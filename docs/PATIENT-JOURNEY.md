# The patient journey, end to end

One patient, from registration at the front desk to the bill, the certificate and the patient's own
view in the portal. Every step below is exercised **through the real API, in this order, on one new
patient** by `apps/api/test/journey.test.ts` (41 tests; each stage asserts that it sees what the
stage before produced):

```bash
npm test -w apps/api -- journey
```

The table is also the map for walking the same story in the browser. "Where in the app" gives the
route, the menu entry as **Module › Page** (from `apps/web/src/modules.ts`) and the button or tab
label (English source text). Chart tabs are opened with `?tab=<id>` on the chart route
(`/doctor/patients/:id` for doctors, `/nurse/patients/:id` for nurses).

## Gaps in the web app found on the way

The API allows each of these; the browser does not (yet) lead there.

1. **A checked-in appointment cannot be completed by the doctor.**
   `apps/web/src/pages/doctor/DoctorSchedule.tsx` (`ACTIONS`, line 31) has buttons for `REQUESTED`
   and `CONFIRMED` only. After reception presses _Check in_ the row has no button, although the
   API allows `CHECKED_IN → COMPLETED / NO_SHOW` for the doctor. Add a `CHECKED_IN` entry
   (**Complete**, **No-show**).
2. **The arrived patient disappears from the doctor's home page.**
   `apps/web/src/pages/doctor/DoctorHome.tsx` line 162 keeps only `CONFIRMED` and `REQUESTED` under
   _Upcoming appointments_; the notification _Your patient has arrived_ therefore leads to a list
   without that patient. Include `CHECKED_IN` (ideally first, marked as arrived).
3. **Registration ends in a dead end for reception.**
   `apps/web/src/pages/doctor/RegisterPatient.tsx`: the success screen offers only _Back to
   patients_ / _Register another patient_ – no **Book appointment** for the person just registered –
   and tells reception _You have been added to the patient's care team_ (also in the page subtitle),
   which is true for doctors only.
4. **Chart links that nurses (and pharmacists) cannot open.** These pages are open to nurses but
   link to the doctor-only route `/doctor/patients/:id`:
   `pages/nutrition/NutritionPage.tsx` lines 237 and 299; `pages/infection/InfectionPage.tsx` lines
   562 and 609 (the same file has `patientBase(role)` for its other links). Either use the role's
   base path (`useChartRole().base`), or let `/doctor/patients/:id` redirect nurses to
   `/nurse/patients/:id` keeping the query string. (Notification links were fixed in the API, see
   below.)
5. **No page for the national medicine catalogue.** The Ministry can only add or change catalogue
   items through the API (`POST` / `PATCH /stock/catalog`); the web app only reads the catalogue.
   That includes the pack barcode needed for bedside scanning.
6. Smaller: on the ward only laboratory staff can mark a specimen as taken (`/lab` → _Specimen
   taken_); a ward nurse who draws the blood has no button for it.

## Defects the journey exposed in the API (fixed, covered by the journey test)

- **Care-team notifications sent nurses to the doctor's chart route.** A notice to the whole care
  team (correction requests, documents, death certificates, identity changes, …) carried
  `/doctor/patients/:id`, which refuses nurses. `notifyUsers` now writes each recipient's link for
  their own workspace (`linkForRole` in `modules/notifications/notifications.service.ts`).
  Covered by stage _s_ ("every notification link opens in the recipient's own workspace").
- **A sepsis prompt outlived the hospital stay.** After discharge an unanswered prompt stayed on
  the _Sepsis_ board for 24 hours and, an hour later, the worker sent "Sepsis screen not done after
  one hour – {ward}, bed {bed}" for a bed that may already hold another patient. Board and worker
  now only consider patients who are still admitted or in the emergency department of that facility
  (`stillInCare` in `modules/sepsis/sepsis.service.ts`). Covered by stage _k_.
- **A pack barcode could never be registered.** `medication_catalog.barcode` (and `ingredients`)
  could only be set by the demo seed, so outside the demo no pack scan could ever be confirmed and
  every bedside dose needed an override reason. `POST` / `PATCH /stock/catalog` now accept
  `barcode` (a GTIN with a valid check digit, unique) and `ingredients`. Covered by stages _g_ and
  _j_ (wristband + pack scanned; the wrong pack stops the dose).

## Notes

- Direct database access in the journey test is limited to: seeding the drug-interaction reference
  data (a deployment seed), reading audit and notification rows to check what was recorded, and
  running the sepsis escalation worker once (workers have no API).
- The story uses a direct (elective) admission. The emergency-department path (arrival, triage,
  treatment, admission from the ED) is covered by `test/ed.test.ts` and `test/inpatient.test.ts`.
- The facility "vaccinations due" list is the childhood calendar; its updating when a dose is
  recorded is covered by `test/vaccination.test.ts`, not by this adult patient.
